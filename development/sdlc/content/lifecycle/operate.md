---
title: 7. Operate
---

Delivery is complete only when the solution can be securely supported.

## Operational Activities

- production verification
- monitoring and alerting
- incident response
- vulnerability and dependency management
- backup verification
- performance and cost monitoring
- documentation maintenance
- access reviews
- model or prompt review where AI remains part of the solution
- post-implementation review
- lessons learned
- backlog of improvements

## Service Operations Handover

Before Gate 5 is approved, the service must be registered in the ICT Service Operations framework. The following KB processes apply:

| Process | KB Reference | Handover Requirement |
|---|---|---|
| Incident Management | [KB Incident Management](https://blank-look.github.io/opencode/knowledgebase/docs/service-operations/incident-management.html) | P1-P4 severity levels defined, on-call contacts documented |
| Problem Management | [KB Problem Management](https://blank-look.github.io/opencode/knowledgebase/docs/service-operations/problem-management.html) | Known error log established, RCA triggers defined |
| Request Fulfilment | [KB Request Fulfilment](https://blank-look.github.io/opencode/knowledgebase/docs/service-operations/request-fulfillment.html) | Service request catalogue entries created |
| User Management | [KB User Management](https://blank-look.github.io/opencode/knowledgebase/docs/service-operations/user-management.html) | User lifecycle (creation, modification, removal) documented |

## Gate 5 — Operational Acceptance

The operational owner accepts:

- the service
- support responsibilities
- documentation
- monitoring
- known risks
- ongoing costs
- maintenance requirements

The final decision is: **Accept, Remediate, Roll Back or Retire**
