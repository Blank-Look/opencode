Security Assessment

All new suppliers, applications, and services must undergo a security assessment before onboarding. This process ensures that security risks are identified and addressed before systems access school data.

Scope

Applies to:

  • New third-party suppliers and vendors
  • New SaaS applications and cloud services
  • New on-premises applications
  • Major version upgrades or material changes to existing services

Assessment Process

  1. Initiation — Business owner submits request with service details
  2. Classification — Determine sensitivity (Low / Medium / High)
  3. Questionnaire — Supplier completes security questionnaire based on sensitivity tier
  4. Review — Security team evaluates responses and supporting evidence
  5. Verdict — Approved, Approved with conditions, or Rejected
  6. Onboarding — Approved services proceed with conditions tracked in asset register

Assessment Criteria

  • Data classification and handling
  • Authentication and access controls (SSO, MFA, RBAC)
  • Data residency and privacy
  • Encryption (at rest and in transit)
  • Logging and monitoring capabilities
  • Incident response and breach notification
  • Sub-processor arrangements
  • Certifications and compliance (SOC 2, ISO 27001, etc.)

Roles

Role Responsibility
Business Owner Submits request, provides business context
Security Team Conducts assessment, determines verdict
Applications Team Reviews technical integration aspects
Procurement Manages contractual and legal review
