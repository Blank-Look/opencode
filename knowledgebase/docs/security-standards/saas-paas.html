Minimum Security Standards: SaaS and PaaS

The Institution is committed to protecting the privacy of its students, alumni, faculty, and staff, as well as protecting the confidentiality, integrity, and availability of information important to the Institution's mission.

Minimum Security Standards: SaaS and PaaS

  1. Determine the risk level by reviewing the data risk classification examples and selecting the highest applicable risk designation across all. For example, an endpoint storing Low Risk Data but used to access a High Risk application is designated as High Risk.
  2. Follow the minimum security standards in the table below to safeguard SaaS and PaaS.
Standard What to do Low Risk Moderate Risk High Risk
Product Selection Follow the approved cloud solution selection workflow for choosing and purchasing a cloud solution. ✓ ✓ ✓
Pre-implementation Planning
  • Follow the SaaS considerations checklist.
  • Follow the PaaS considerations checklist.
  • Follow the security guidelines for using a cloud product.
 ✓ ✓ ✓
Inventory and Asset Classification Review and update cloud inventory records quarterly. Must indicate associated risk classification, data volume estimates, and service ownership. ✓ ✓ ✓
Credential and Key Management
  1. If possible, integrate with the Institution's single sign-on (SSO) services, preferably SAML.
  2. Review administrative accounts and privileges quarterly.
  3. Adhere to password complexity rules if not integrated with an SSO service.
  4. API keys:
    • Minimize their generation.
    • Grant minimum necessary privileges.
    • Rotate at least annually.
    • Do not hardcode.
  5. Do not share credentials.
 ✓ ✓ ✓
Encryption
  1. Enable transport layer encryption — TLS 1.2 or higher.
  2. Use encryption of data at rest if available.
 ✓ ✓ ✓
Two-Step Authentication If user login cannot be integrated with the Institution's SSO, enable two-factor authentication if offered by the solution. — ✓ ✓
Logging and Auditing
  1. Enable any available application logging that would assist in a forensic investigation in the event of a compromise. Seek vendor or security office guidance as needed.
  2. Contractually ensure that the provider can export logs on request within five days.
 — ✓ ✓
Data Management Contractually ensure that Institution data are purged upon termination of the agreement, with accommodations as necessary to comply with any applicable regulatory obligations. — ✓ ✓
Secure Admin Workstation

Administration consoles should only be accessed through a Privileged Access Workstation (PAW) when logging in with an administrative account. A PAW is required for privileged (ring0) access.

Administrative accounts are defined as:

  1. Accounts with the ability to make unrestricted, potentially adverse, or system-wide changes.
  2. Accounts with the ability to override or change security controls.
 — — ✓
Security, Privacy and Legal Review Follow the Data Risk Assessment process and implement recommendations prior to deployment. — — ✓
Regulated Data Security Controls
  1. Follow all regulatory data controls as applicable.
  2. For protected health data, ensure that only cloud services covered under a business associate agreement are used.
