Module 6: GitHub Actions

Push → workflow starts → tests → deploy docs. Automation without deep YAML.

Self-paced · ~45 min

Read

What is GitHub Actions?

GitHub Actions is automation triggered by events in your repository. When something happens (push, PR, schedule), a workflow runs. Workflows are defined in YAML files in .github/workflows/.

Key concepts:

  • Event: What triggers the workflow — push, pull_request, schedule, workflow_dispatch
  • Job: A unit of work that runs on a runner (GitHub-hosted or self-hosted)
  • Step: Individual action within a job — run a command, use a marketplace action, etc.

Reading a workflow YAML

Walk through this example line by line:

# .github/workflows/deploy-docs.yml
name: Deploy Documentation

on:
  push:
    branches: [main]

jobs:
  build-and-deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Build with MkDocs
        run: mkdocs build
      - name: Deploy to Pages
        uses: peaceiris/actions-gh-pages@v3

Parts to understand:

  • name — appears in the Actions tab
  • on: push: branches: [main] — triggers when anything is pushed to main
  • runs-on — the OS the job runs on
  • uses — reference a marketplace action
  • run — execute a shell command

Use cases

  • Documentation deploy: Push Markdown → Action runs MkDocs → Site updates. Your docs are always current.
  • CI checks: Push code → Action runs tests → Pass/fail reported on the PR. Never merge broken code.
  • Linting: Check Markdown formatting, YAML validity, PowerShell syntax.
  • Scheduled tasks: Run a script every morning to clean up stale issues.
  • Teams notifications: Send a message to Teams when a PR is opened or merged.
  • Manual trigger: workflow_dispatch lets you run workflows on demand from the GitHub UI.

The GitHub Marketplace has thousands of pre-built actions. You rarely need to write one from scratch. Common ones: actions/checkout, actions/setup-node, azure/login, peter-evans/create-pull-request.

Exercise — Docs Deploy

Create a workflow file in your practice repository at .github/workflows/deploy-docs.yml using the template above. Then:

  • Edit a Markdown file in your docs folder
  • Create a branch, commit, push, open a PR
  • Watch the Action run in the PR checks (go to the Actions tab)
  • Merge the PR
  • Verify the documentation site updated automatically

If the workflow fails, click the failed step in the Actions tab and read the log output to diagnose the issue.

Common pitfalls

  • YAML indentation: YAML is whitespace-sensitive. Use two spaces per indent level. Tabs will break it.
  • Workflow not triggering: Check the on: event. Did you push to the right branch?
  • Secrets: Never hardcode passwords or tokens in the workflow file. Use GitHub Secrets.
  • Logs: When a workflow fails, click the failed step to see the log output. The error message is usually clear.
