Module 3: Git Basics

Clone, status, add, commit, push, pull. The six commands you'll use every day.

Self-paced · ~1.5 h

Read

What is Git?

Git is a version control system. It tracks every change to every file in a repository. Think of it as "undo for your entire project, forever."

The four states of a file in Git:

  • Working: You've edited the file. Git sees the change but isn't tracking it yet.
  • Staged: You've told Git which changes to include in the next commit (git add).
  • Committed: You've saved a snapshot of the staged changes (git commit).
  • Pushed: You've sent your commits to GitHub (git push).

Clone

Open your terminal and run git clone <url> to download the entire repository — all files, all history, all branches — to your machine.

$ git clone https://github.com/team/training-repo.git
# Creates a folder called training-repo/

Status and staging

git status will be your most-used command. Run it to see what's changed, what's staged, and what's untracked.

$ git status
# Shows modified files, staged files, untracked files

git add <file> stages a file. git add . stages all changes in the current directory.

Commit

git commit -m "message" saves a snapshot. Your message should be present tense and descriptive. You should see a confirmation like [main abc1234] Your message.

$ git add README.md
$ git commit -m "Add Intune packaging documentation"
# [main abc1234] Add Intune packaging documentation

Push and pull

git push sends commits to GitHub. git pull fetches and merges changes from GitHub.

$ git push
# Sends commits to GitHub
$ git pull
# Gets latest changes from teammates

Always run git pull before you push. If someone else pushed since your last pull, Git will show a "rejected" error.

Try it yourself

Open your terminal and run through the full cycle:

  • Clone a repository
  • Edit a file
  • Run git status
  • Stage with git add
  • Commit with a message
  • Push to GitHub
  • Check that the commit appears on GitHub.com

Exercise — Your own test repo

Create a test repository on GitHub, clone it to your machine, add a file, commit, and push the change. Then edit the file, commit again, and push again. Practice the full cycle at least three times until the commands feel automatic.

# Full cycle recap
$ git clone https://github.com/YOUR-USER/YOUR-REPO.git
$ cd YOUR-REPO
$ echo "# My project" > README.md
$ git status
$ git add README.md
$ git commit -m "Add README"
$ git push
# Edit the file in your editor, then repeat add-commit-push

Common pitfalls

  • Not cloning: Some people try to git init in an empty folder. Always clone first.
  • Forgetting to stage: git commit without git add commits nothing. Run git status to check.
  • Vague messages: "update" or "fix" are useless. Write what changed and why.
  • Pushing before pulling: If you get a "rejected" error, run git pull first, then push.
