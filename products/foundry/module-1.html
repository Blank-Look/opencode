Module 1: Why GitHub?

Why SharePoint is the wrong tool. Git vs GitHub. Core features. How AI fits in.

Script & talking points

Opening (5 min)

Welcome to Foundry. Over two days we'll build your team's GitHub baseline. By the end, every person will be able to clone a repo, make changes, open a pull request, and get their work reviewed and merged.

This isn't a developer bootcamp. You're M365 infrastructure engineers. Everything we do — every example, every exercise — is based on the work you actually do. Intune packaging, Azure landing zone docs, PowerShell scripts, Teams automation. Real work.

Facilitator note

If anyone expresses anxiety about "not being a developer," address it immediately. GitHub is for docs and config, not just code. Emphasise that Markdown is easier than Word once you know 5 syntax rules.

Why not SharePoint? (5 min)

Ask the room: "Where do we store our documentation today?" The answer will be SharePoint, network drives, or Teams. Then ask: "What happens when two people edit the same file?"

SharePoint's problems for engineering work:

  • Version history is per-file. You can't see the state of the whole doc set at a point in time.
  • No branching. You can't experiment safely. Every edit is live or you're working on a copy.
  • No review workflow. Someone uploads a file and it's done. No one else sees it before it's published.
  • No automation. You can't trigger tests, deployment, or validation when a file changes.
  • No integration. AI tools don't plug into SharePoint docs the way they plug into GitHub.

GitHub treats everything as code — docs, config, scripts, policies. That means you get version control, branching, review, automation, and AI integration. One platform. Consistent workflow.

Key message: GitHub is not "another tool to learn." It's the tool that makes all your other tools work better.

Git vs GitHub (5 min)

Git is the version control engine. It runs on your machine. It tracks changes, creates commits, manages branches. You interact with it through commands like git add, git commit, git push.

GitHub is the hosting platform. It stores repositories online, adds collaboration features (Pull Requests, Issues, Projects), and connects to automation and AI tools.

Analogy: Git is the engine. GitHub is the car. You need both to go anywhere.

Whiteboard exercise

Draw two columns. Left: what Git does (local, command-line, version tracking). Right: what GitHub adds (remote hosting, PRs, issues, Actions, AI). Ask participants to suggest items for each column.

Core concepts tour (10 min)

Open a GitHub repository live. Walk through each tab:

  • Code tab: Files, commit history, branches dropdown. Show the README rendering.
  • Issues tab: Show an issue. Explain: tasks, bugs, feature requests. Labels, assignees, comments.
  • Pull Requests tab: Show an open PR. Explain: propose changes, review, discuss, merge.
  • Actions tab: Show a completed workflow run. Explain: automation triggered by push or PR.
  • Wiki / Projects: Mention briefly — documentation and Kanban boards.
Live demo tips

Use the training repository. Have at least one open issue and one open PR ready to show. If you have a workflow that already ran, even better — showing the green checkmark on a PR is a powerful moment.

AI and GitHub (5 min)

GitHub is the single source of truth that AI tools connect to:

  • ChatGPT: Generate READMEs, PowerShell scripts, documentation. Paste the output directly into your repo.
  • Copilot: Inline code completions in VS Code. Suggests what to type next based on your comments and code.
  • OpenCode / Claude Code: Terminal-based agents. Give them a prompt, they build files, run commands, commit changes. Review and approve.

Golden rule: AI generates. Humans approve. Never commit AI output without reading it first.

Key takeaway

"GitHub is where your engineering work lives. AI, automation, and collaboration all connect through it."
