Module 1: Why GitHub?

Why SharePoint is the wrong tool. Git vs GitHub. Core features. How AI fits in.

Self-paced · ~30 min

Read

Your learning path

Welcome to Foundry. In this module you'll build your GitHub baseline. By the end you'll understand why GitHub matters for your work, how it differs from what you use today, and how its core features—and AI—fit together.

This isn't a developer course. You're an M365 infrastructure engineer. Every concept here is based on the work you actually do: Intune packaging, Azure landing zone docs, PowerShell scripts, Teams automation. Real work.

Why not SharePoint?

Think about where you store your documentation today. SharePoint? Network drives? Teams? Now consider: what happens when two people edit the same file at the same time?

SharePoint's problems for engineering work:

  • Version history is per-file. You can't see the state of the whole doc set at a point in time.
  • No branching. You can't experiment safely. Every edit is live or you're working on a copy.
  • No review workflow. Someone uploads a file and it's done. No one else sees it before it's published.
  • No automation. You can't trigger tests, deployment, or validation when a file changes.
  • No integration. AI tools don't plug into SharePoint docs the way they plug into GitHub.

GitHub treats everything as code — docs, config, scripts, policies. That means you get version control, branching, review, automation, and AI integration. One platform. Consistent workflow.

Key message: GitHub is not "another tool to learn." It's the tool that makes all your other tools work better.

Git vs GitHub

Git is the version control engine. It runs on your machine. It tracks changes, creates commits, manages branches. You interact with it through commands like git add, git commit, git push.

GitHub is the hosting platform. It stores repositories online, adds collaboration features (Pull Requests, Issues, Projects), and connects to automation and AI tools.

Analogy: Git is the engine. GitHub is the car. You need both to go anywhere.

Core concepts tour

Open any GitHub repository — for example, the OpenCode repo — and explore the tabs yourself:

  • Code tab: Browse the files, look at the commit history, check the branches dropdown. See how the README renders.
  • Issues tab: Browse open issues. Each one is a task, bug, or feature request with labels, assignees, and comments.
  • Pull Requests tab: Look at open or closed PRs. Each one proposes changes, includes discussion, and ends with a merge.
  • Actions tab: Find a completed workflow run. This is automation triggered by a push or PR — tests, deployments, validation.
  • Wiki / Projects: Documentation and Kanban-style project boards.

Spend a few minutes clicking through each tab. This is the interface you'll be working with every day.

AI and GitHub

GitHub is the single source of truth that AI tools connect to:

  • ChatGPT: Generate READMEs, PowerShell scripts, documentation. Paste the output directly into your repo.
  • Copilot: Inline code completions in VS Code. Suggests what to type next based on your comments and code.
  • OpenCode / Claude Code: Terminal-based agents. Give them a prompt, they build files, run commands, commit changes. Review and approve.

Golden rule: AI generates. Humans approve. Never commit AI output without reading it first.

Try it

Open the OpenCode repository (or any public repository) in a new tab. Spend 5–10 minutes exploring:

  • Click the Code tab and browse the file tree. Open a file to see its contents. Switch branches using the dropdown.
  • Click the Issues tab. Read through one or two open issues. See how they're labelled and assigned.
  • Click the Pull Requests tab. Find a merged PR and read through the conversation and the diff.
  • Click the Actions tab. Look at a completed workflow run to see what steps it executed.

Don't worry if some of these tabs are empty — every repository is different. The goal is to get comfortable navigating the interface.
