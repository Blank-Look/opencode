Script & talking points

Why standards matter (5 min)

Every repository should look the same. When a new engineer joins and opens a repo, they should know exactly where to find docs, scripts, and config. Consistency removes cognitive load.

  • Onboarding: New team members can navigate any repo immediately
  • Automation: Tools and workflows can rely on consistent paths
  • Review: PRs are easier to review when the structure is predictable

Standard layout (10 min)

my-repo/
├── README.md # Project description, usage, owners
├── docs/ # Documentation (Markdown)
├── scripts/ # PowerShell, bash scripts
├── .github/ # GitHub config: workflows, templates
│ ├── workflows/
│ └── CODEOWNERS
├── .gitignore
├── LICENSE
└── src/ (if applicable) # Source code (PowerShell modules, etc.)

README, LICENSE, CODEOWNERS (5 min)

README.md: Every repo needs one. Include: project title, one-line description, how to use it, who owns it, where to get help.

LICENSE: Always include one. Internal repos can use "UNLICENSED" (all rights reserved) or MIT. Never leave it out — without a license, others can't legally use the code.

CODEOWNERS: File at .github/CODEOWNERS. Defines who is automatically requested for review when files in certain paths are changed.

# .github/CODEOWNERS
* @team-lead # Default owner for all files
/docs/ @docs-team # Docs changes reviewed by docs team
/scripts/ @eng-team # Script changes reviewed by eng

.gitignore and naming conventions (5 min)

.gitignore prevents committing files that shouldn't be in version control:

  • Secrets and credentials (.env, *.key)
  • Build artifacts (node_modules/, dist/)
  • OS files (.DS_Store, Thumbs.db)
  • IDE config (.vscode/, .idea/)

Naming conventions:

  • Lowercase with hyphens: intune-packaging, azure-lz-docs, entra-id-scripts
  • Descriptive but short: teams-automation, not microsoft-teams-automation-scripts-and-tools
  • No spaces, no uppercase, no underscores
Template repositories

GitHub allows marking a repo as a template. When someone creates a new repo from a template, they get all the files and structure. Set one up for your team with the standard layout, README template, CODEOWNERS, .gitignore, and LICENSE pre-configured.

Exercise — Build a Repository (30 min)

Instructions

Each person creates a new repository (or uses the team template). Add:

  • README.md with title, description, install steps, and owner
  • docs/ folder with one documentation page
  • .github/CODEOWNERS with themselves as default owner
  • .gitignore for PowerShell projects
  • LICENSE file (MIT or UNLICENSED)

Commit and push. Show the final repository structure on GitHub.
