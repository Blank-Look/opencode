Module 2: Markdown

Headings, lists, tables, links, images, code blocks, Mermaid diagrams.

Self-paced · ~1 h

Read

Why Markdown?

Markdown is plain text that renders as formatted HTML. Every GitHub repository uses it. README, Issues, PR descriptions, Wiki pages — all Markdown.

Why Markdown instead of Word or Google Docs?

  • Plain text. Any editor works. It's versionable — Git can diff every change.
  • Portable. A Markdown file from 2014 still renders correctly today. No vendor lock-in.
  • Reviewable. Changes show up in Pull Requests line by line. No "track changes" mess.
  • Everywhere. GitHub, Teams, VS Code, Obsidian, Notion — all support Markdown.

Headings & text

Try each syntax and see how it renders:

# Heading 1 (document title, use once)
## Heading 2 (section)
### Heading 3 (subsection)

**Bold text** — double asterisks
*Italic text* — single asterisk
~~Strikethrough~~ — double tilde

Unordered list:
- Item one
- Item two
  - Sub-item

Ordered list:
1. First
2. Second

Use one # Heading 1 per document as the title. Sections use ## and ###.

Links, images, tables

[Link text](https://example.com)
![Alt text](image.png)

| Header 1 | Header 2 | Header 3 |
|----------|:--------:|--------:|
| Left | Center | Right |
| Cell | Cell | Cell |

For tables, the colon in the separator row controls alignment: :--- left, :---: center, ---: right. Without colons, default is left-aligned.

Relative links: Link between docs in the same repository using relative paths: [Policy](docs/policy.md). These work on GitHub and in cloned repos.

Code blocks & Mermaid

Code blocks use triple backticks. The language name after the opening backticks enables syntax highlighting:

```powershell
Get-IntuneCompliancePolicy | Export-Csv -Path policies.csv
```

```yaml
name: Deploy Docs
on: [push]
```

```mermaid
graph LR
  A[Requirement] --> B[Build]
  B --> C[Review]
  C --> D[Deploy]
```

Mermaid is embedded diagramming. Fenced code blocks with ```mermaid render as flowcharts, sequence diagrams, Gantt charts, and more. GitHub renders them automatically.

Now try it yourself

Create a README.md that includes:

  • Heading: "Intune Application Packaging Repository"
  • Description paragraph
  • Table with 3+ apps (App Name, Version, Install Command)
  • A PowerShell code block showing a sample install command
  • A Mermaid flowchart showing: Request → Package → Test → Deploy
  • A link to the team's documentation standards

Common pitfalls

  • Space after #: #Heading doesn't work. Must be # Heading.
  • Blank lines before headings: Not always required but improves readability.
  • Table pipes not aligned: Pipes don't need to be visually aligned in the source, but they're easier to read if they are.
  • Mermaid rendering on GitHub: Only renders in Markdown files on GitHub.com, not in all contexts. Still write them — they work in PRs and the Code tab.
