Minimum Security Standards: IaaS and Containerized Solutions

Applicability

  1. The minimum security standards found here apply to IaaS managed services — virtual servers that are designed to be ephemeral — and containerized solutions.
  2. All other persistent virtual servers, regardless of infrastructure, are to be managed under the Minimum Security Standards: Servers.
Standard What to do Low Risk Moderate Risk High Risk
Platform Selection Follow the approved cloud solution selection workflow for choosing and purchasing a cloud solution. ✓ ✓ ✓
Operational Practices As far as possible, apply the cloud operational principles and practices. ✓ ✓ ✓

Patching and Application Lifecycle
  1. Apply high severity security patches within seven days of release.
  2. Apply all other security patches within 90 days.
  3. Use a supported operating system and application version.
  4. Use machine images only from trusted sources.

Additional elaboration:

  • Managed services — For provider-managed database and platform services, define a maintenance window that meets the standard.
  • Ephemeral servers and containers — If using an automated system to build fully patched machine images, ensure that the patched image, or container base layer, is in use in your environment within the window of time specified in the standard.
 ✓ ✓ ✓
Vulnerability Management

Based on public vulnerability database ratings, identify and remediate severity 4 and 5 vulnerabilities within seven days of discovery, and severity 3 vulnerabilities within 90 days.

The Institution provides and recommends the approved vulnerability scanning service; however, platform-specific native scanning tools may be used instead. If a detection tool other than the approved service is used, the security office may request a review and audit of the tool and practices, as well as periodic verification of efficacy.

Additional elaboration:

  • Managed services — Scanning may be omitted on provider-managed services; however, if the platform provides a native vulnerability detection capability, it should be implemented.
  • Ephemeral servers — Build machine images that contain the appropriate agent, or bootstrap the installation and configuration of the agent using the management tools specific to your implementation.
  • Containerized solutions — Scan images for known vulnerabilities using a container image scanning tool or similar capability.
 ✓ ✓ ✓
Inventory and Asset Classification

Review and update cloud inventory records quarterly. Must indicate associated risk classification and service ownership.

Additional elaboration:

  • Ephemeral servers — Systems designed for a lifespan of no greater than seven days (commonly those in autoscaling worker groups) should be inventoried as a single application.
  • Managed services — Provider-managed database and platform services should be inventoried as applications.
 ✓ ✓ ✓
Firewall Use the native tools and design patterns of your platform to ensure that only the minimum necessary network communication is permitted through virtual network devices such as virtual networks, load balancers, and the like. This includes access to managed services such as hosted database platforms. ✓ ✓ ✓
Credential and Key Management
  1. Where possible, integrate with the Institution's SSO authentication for all cloud administration consoles.
  2. Abide by password complexity rules.
  3. Review administrative accounts and privileges quarterly.
  4. API keys:
    • Minimize their generation.
    • Grant minimum necessary privileges.
    • Rotate at least annually.
    • Do not hardcode.
  5. Do not share credentials.
 ✓ ✓ ✓
Two-Step Authentication Enforce two-factor authentication for all interactive user and administrator logins. The Institution's two-step authentication service is recommended, but other two-factor options are acceptable. — ✓ ✓
Logging and Alerting
  1. Enable any available application logging that would assist in a forensic investigation in the event of a compromise. Seek vendor or security office guidance as needed.
  2. Forward logs to remote logging solutions. The centralized logging service is recommended, but third-party solutions are also acceptable.

Additional elaboration:

  • Administrative activity logs — Log user actions and API calls that create or modify the configuration or metadata of a resource, service, or project.
  • Data access logs — Log user actions and API calls that create, modify, or read High Risk data managed by a service.
 — ✓ ✓
Backups
  1. Back up application data at least weekly.
  2. Encrypt backup data in transit and at rest.
  3. Store backups in independent cloud accounts.
 — ✓ ✓
Encryption
  1. Enable transport layer encryption for all communications external to the private cloud environment.
  2. Use TLS 1.2 or higher.
  3. Use encryption at rest if available.
 — ✓ ✓
Data Centers Prefer data center locations in approved jurisdictions. — ✓ ✓
Secure Admin Workstation

Cloud administration consoles should only be accessed through a Privileged Access Workstation (PAW) when logging in with an administrative account. A PAW is required for privileged (ring0) access.

Administrative accounts are defined as:

  • Accounts with the ability to make unrestricted, potentially adverse, or system-wide changes.
  • Accounts with the ability to override or change security controls.

Regulated Data Security Controls
  1. Adhere to applicable regulations and contractual obligations.
  2. For protected health data, ensure that only cloud services covered under a business associate agreement are used.
