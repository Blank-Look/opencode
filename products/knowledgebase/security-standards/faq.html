Minimum Security Standards: Frequently Asked Questions

Common questions about compliance, exceptions, patching, vulnerability management, and the individual standards.

Compliance and Exception Process

When is a standard exception needed?

When a standard as a whole cannot be met. For example, an exception is not needed when a single, or small subset of, patches cannot be applied as specified by the Patching standard.

How do I get started bringing my servers into compliance with the Minimum Security Standards?

The Information Security Office has developed quick start guides for managed Linux and Windows servers. See the cookbooks for more information.

What if I cannot meet some or all of the Minimum Security Standards for my servers, applications, or endpoints? Can I request a compliance exception? Who should submit the request?

If you cannot meet some or all of these standards for your servers or applications, fill out a temporary exception request. These requests should be submitted by the server or application business owner. If you cannot meet some or all of these standards for your endpoints, fill out the temporary compliance exception request form. These requests should be submitted by the endpoint's primary user.

Is there a different process for processing exception requests for endpoints vs. servers and applications?

Yes. The endpoint compliance exception request starts a review process that is managed in one tracking system, while the server and application exception request starts a review process managed in the service management platform.

Do I need to submit a temporary exception request for each of my servers/applications?

You can submit one exception request for all servers/applications for which you want an exception from the same standard(s).

My current system/application is not compliant, but will be replaced by a different system/application in the future. I don't want to divert resources to update a system that is going to go away. Can I submit an exception until the old system is decommissioned?

No. If a system/application is not meeting compliance, but there is a plan to replace it with a newer compliant system, the existing system will simply stay non-compliant until decommissioned.

What are the eligibility criteria for a temporary exception for my server or application?

A server or application is eligible if:

  • It is not supported by an up-to-date OS or application version.
  • The OS or application cannot meet a specific standard because of a technical dependency. An exception may be granted on a case-by-case basis as long as there is an upgrade plan on a system that is scheduled to be decommissioned or replaced by another system.
  • No updates are available for a vendor supported system.
  • The system does not support password complexity requirements.

How long does an exception last?

An approved temporary exception for servers/applications will be valid for up to three years at the discretion of the Information Security Office. An approved temporary exception for endpoints will be valid for up to one year.

I am having trouble meeting the deadline for my systems; can I get an extension by submitting an exception request?

Exception requests are intended for servers and applications that cannot meet the standards, not as an extension for compliance deadlines.

Patching

I cannot patch my system because the reboot will cause an outage of the service to my end users.

System managers and business owners should have negotiated maintenance windows for their systems that allow for the application of security patches on a schedule that is in compliance with the Minimum Security Standards.

I cannot patch my system because I am unsure whether the patches will break a custom application.

System managers should have test environments in place to perform impact analysis of changes to their environment. Exception requests will not be granted based on a suspicion of an impact that has not been validated by testing or vendor input.

Vulnerability Management

Where can I get an overview of my systems' information security vulnerabilities?

Request an account with the approved vulnerability scanning service, then sign in to view vulnerabilities.

For reported vulnerabilities, do I need to address "potential" vulnerabilities or just "confirmed" vulnerabilities?

In order to meet compliance, both potential and confirmed vulnerabilities need to be addressed.

If a scan shows a vulnerability and there is no patch available from the vendor, is an exception needed?

No. If there is no patch from a vendor for a reported vulnerability, an exception is not needed. In the absence of a patch, explore other alternate solutions and compensating controls that may be recommended by the vendor.

How do I handle false-positive vulnerabilities?

If a scan shows a vulnerability that is investigated and found to be a false positive, an exception is not needed. Mark the false-positive vulnerability as ignored and denote that the vulnerability is a false positive in the comments section.

Who is responsible for updating false positives?

Each organization is responsible for managing its own assets in the scanning service, including ignoring vulnerabilities that are false positives.

How can I request API access?

Submit a request for an API account. The security office will work with you to identify the appropriate API account permissions.

What does "remediate" mean in the Vulnerability Management standard?

To investigate identified vulnerabilities, ignoring false positives, addressing any configuration problems, and/or applying patches when available from the vendor.

Whole Disk Encryption

Is the startup pin required to be compliant for whole disk encryption?

It is highly recommended that all full-disk encryption features, including a startup pin, be utilized; however, the startup pin can be removed for systems that require unattended reboots.

Inventory

Who should be updating each organization's IT system inventory records each month to reflect current adoption status?

Each organization has designated a point person who is accountable for ensuring that their inventory records and adoption status are updated on a monthly basis. The operations owner for each server and/or application is responsible for informing the associated business owner of any changes, and for providing this information to the accountable point person to make the update, unless the point person has delegated the responsibility.

Firewall

Do host-based firewalls have to be configured to allow port scanning by the vulnerability scanning service?

Host-based firewalls should permit only the minimum necessary ports/protocols, blocking everything else that does not support a business need. A system administrator should not explicitly block the scanner's source addresses. Network-based firewalls should permit security scans to pass through unfettered.

Two-Step Authentication

If I have two-step authentication on my VPN, do I still need it on my server?

Yes, two-step authentication must be installed on your server to comply with the Minimum Security Standards.

I am running a system that does not support two-step authentication. What is an adequate compensating control?

Any authentication mechanism that enforces two-step authentication is a suitable compensating control for systems that do not support native two-step authentication. Alternatively, the network access control service can also be used as a compensating control.

Centralized Logging

Is sending logs to the centralized logging service required to meet this standard?

While the centralized logging service is not required, the security office may require logs from critical systems to be forwarded for security monitoring and incident investigation.

Sysadmin and Developer Training

How can I tell if someone completed a training course this calendar year?

Ask the employee to review their training history and send you their completion certificate or a screen capture of the completed course.

How can I satisfy the sysadmin/developer training requirement if I cannot attend one of the in-person classes?

You can take one of the online (self-paced) classes which does not require previous completion of the introductory information security course.

Malware Protection

How do I satisfy the Malware Protection and Intrusion Detection standards on my Windows server?

Windows servers can satisfy both of these requirements by implementing the approved anti-malware agent.

Intrusion Detection

How do I satisfy the Intrusion Detection standard on my Linux server?

Linux servers satisfy the Intrusion Detection requirement by implementing a file integrity monitoring agent. Legacy systems that cannot run the agent can also satisfy this requirement using an alternative file integrity tool.

Physical Protection

What kind of data center do I need to comply with the Physical Protection standard?

The system administrator should use their own judgment. The intent of this standard is to ensure that servers cannot be easily stolen. Servers should be housed behind a locked door, and access should be restricted to authorized system administrators only, preferably with a spring-loaded door, video surveillance, and a card reader. A locked office does not suffice.

Dedicated Admin Workstation

What is a PAW and who needs one?

See the Privileged Access Workstation (PAW) service page for more information about PAWs and who is required to obtain one.

Security, Privacy, and Legal Review

Do I need to file a privacy, security, and legal review for my existing systems?

No, a privacy, security, and legal review is not needed for existing systems.

Regulated Data Security Controls

If my systems meet the Minimum Security Standards, does that mean they are also compliant with specific regulatory requirements?

No. In order to meet specific regulatory security control requirements, your system must also meet the appropriate security requirements for that regulation, including its administrative, technical, and physical security rules.
